## Data layout (repo `data/` folder; same documents the artifact database held)
- `catalog-0..N.json`  — `{rows:[...], date}`; one row per product x colour/scent variant x size x package. `pid` groups the same product across stores (brand + normalised name, see KEY_ALIAS in the scraper for hand-checked merges) and `ck` = pid + size is the cross-store compare key; brand, display name (`line`) and capacity are harmonised per pid. Each row has `cat`: `diaper` (tab brief), `pullup` or `booster`; the page shows one dashboard tab per cat (#diapers, #pullups, #boosters). A row with `bo: true` is a backorder: the store's feed says it can be bought, but its product page says out of stock (shown as "Out of stock · backorder"). Chunks < 200 KB.
- `history-0..N.json`  — `{h:{rowId:[[date, price, inStock], ...]}}`; a point is added only when price or stock changes.
- `thumbs-0..N.json`   — `{t:{"Store|handle":{src, d:dataURI}}}`; 88px WebP thumbnails.
- `meta.json`          — last run time, per-store success/rows/errors, doc counts, Amazon credit use (`amazon`).

2. Load yesterday's data from GitHub. Attach and clone the repo into `./site` as PUBLISH.md step 1 says (`add_repo` with push access, then `git clone --depth 1`). Then:

   If the clone fails, stop: send the owner a push saying "Dip Aisle: tracker not refreshed today — could not read yesterday's data from GitHub: <reason>", no emails.
2b. One-time migration from the artifact database (only while `site/data/` is empty). Needs the ArtifactData tool (ToolSearch "select:ArtifactData"); if it is not available, follow the scheduled task's instruction for that case (push only, no scrape, no email) and stop.

If the counts look wrong, stop and push "Dip Aisle: history migration looked incomplete (<counts>); nothing was changed." — no scrape, no email.

3. `python3 scraper.py ./out ./prev 2> scrape.log` (needs Pillow; keep stderr in `scrape.log` for the data-issue check). It prints a meta JSON with doc counts and writes `out/catalog-i.json`, `out/history-i.json`, `out/thumbs-i.json`, `out/meta.json`. The Rearz step makes a few hundred small requests, and products without a capacity in their description get one extra product-page fetch; the run takes about 4-5 minutes.
3a. `python3 amazon.py ./out ./prev 2>> scrape.log` (added 2026-10-31, owner). Adds Amazon.ca listings for brands the tracker follows plus adult-baby brands (Sunkiss, Little for Big, Rearz, Tykables, ABUniverse, LNGU, Kiddo, Crinklz, Cuddlz, Landofgenie, Bambino). Amazon has no feed, so it reads Amazon.ca search pages through the Firecrawl API (`/v2/scrape`, rawHtml, location CA, proxy basic = 1 credit/page). The owner chose the Firecrawl free plan (1,000 credits/month), so the script spends at most `AMAZON_CREDIT_BUDGET` (default 700) a month: each run gets an even daily share (about 22 searches; up to 1.5x to catch up), searches checked longest ago first, and it stops on HTTP 402 (out of credits). Credit use is kept in `meta.json` → `amazon` (`month`, `used`, `last` per search); the script reads it from `prev/meta.json`. Listings not re-checked today are carried forward with their `checked` date and dropped after 14 days. Needs `./scraper.py` in the same folder (it reuses its brand/name/product-key rules), the key from project doc `dip-aisle/firecrawl.key` saved as `./firecrawl.key` (never print it), and `api.firecrawl.dev` plus `m.media-amazon.com` (thumbnails) on the allowed-domains list. A failure keeps yesterday's Amazon rows; report `meta.stores.Amazon.error` as a PROBLEM. Amazon's own terms forbid scraping; the owner accepted that on 2026-10-31.
3b. `python3 stock_check.py ./out` (added 2026-10-30, owner: AgeComfort Lil Squirts showed in stock but the store page says out of stock). AgeComfort sells many items as backorders, so its `/products.json` says `available: true` while the product page shows "Out of Stock — This item will ship once back in stock". The script reads each AgeComfort diaper/pull-up/booster page on `www.agecomfort.com` (about 100 pages, ~1 minute), takes the per-variant stock badges (`icon-in_stock` / `icon-out_stock`, one for the selected variant then one per variant in the order of the page's schema.org offers), marks those rows out of stock with `bo: true`, and fixes today's history point. It edits `out/` in place and prints `{"pages", "pages_failed", "marked_out_of_stock", ...}`. If `pages_failed` is more than half of `pages`, add a PROBLEM "AgeComfort stock check could not read product pages" with the first error (most likely `www.agecomfort.com` is not on the allowed-domains list); the rows then keep the feed's stock value. Run it before step 4 so the corrected stock is what gets published and what changes.py compares. It also reads Healthwick's `/products.json` descriptions for backorder notes ("PVS-512 (S/M) AND PVS-513 (L) are currently backordered", "this product is on manufacturer backorder") and marks those variants the same way (matched by SKU prefix, or every variant when no SKU is named). MyDips (theme shows the real stock; feed agrees), ABUniverse and Rearz (stock from its price API) were checked 2026-10-30 and need no fix.
4. Publish `./out` to GitHub (the data store) exactly as PUBLISH.md steps 2–4 say: `python3 site/tools/publish.py ./out ./site`, commit and push only `data/`. Never change anything outside `data/`. If it failed, tomorrow's run reads the last pushed data, so today's price points are lost from the history — say so in the PROBLEM.
5. If a store failed, the scraper carries yesterday's rows forward marked `stale`.

Daily report and push (owner request 2026-10-30; the push is sent EVERY day, emails follow step 7's rules): `python3 changes.py ./prev ./out ./scrape.log > changes.json` writes JSON with `price_changes`, `back_in_stock`, `out_of_stock`, `new_listings`, `removed_listings`, `issues`, a one-line `banner` and the full plain-text `report`. 1. reads `ca.rearz.ca/xmlsitemap.php` → product sitemap, keeping disposable diaper/brief/booster/underwear slugs (cloth, wraps, training pants, mixed packs, accessories skipped by slug);
2. fetches each product page for title, description (capacity), breadcrumb, image and the Size/Quantity option ids;
3. calls `ca.rearz.ca/remote/v1/product-attributes/{productId}?attribute[opt]=val&...` for every size x pack combination to get the exact CAD price and stock. (The page HTML only shows the default size's prices, and AI page extraction copied those to other sizes — don't use it for prices.)
Needs `ca.rearz.ca` on the allowed-domains list (thumbnails come from `cdn11.bigcommerce.com`, already reachable). Without it Rearz fails with "cannot reach ca.rearz.ca … allowed-domains list?". No Firecrawl key is needed.

## Parsing rules added 2026-10-28 (from owner feedback on the tracker)
- Package: "Bag (10)" is one bag; only plural "Bags (n)" / "3 Bags (36)" / "Case" are cases.
- Capacity: mL in text, spec labels ("Absorption (ml) 11500"), "11 000 ml", litres ("11 ½ liters", "4.4L", "12L capacity"); mL beats litres. If the description has none, the Shopify product page spec table is read ("Capacity varies by size 6050ml"). Image-only capacities go in `CAP_MANUAL` (owner-confirmed): Mega Safari 11,000 mL, Lil Bella Daytime 6,000 mL.
- Quantities: also "Each package contains 21 briefs, with three packages per case" and "12 in a bag 36 in a case".
- Names: when a title is only brand + generic words, the store title is shown (e.g. "BetterDry Adult Diapers"), not "Briefs".
- Excluded: promos/mixed bags (free samples, unlocked, lucky dip, mystery, grab bag) and products tagged "training pants".
- The page copies each data row before adding display fields.
